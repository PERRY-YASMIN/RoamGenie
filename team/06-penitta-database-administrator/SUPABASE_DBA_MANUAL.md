# Supabase DBA Manual — Penitta A

## Project and access

Create the development project in the agreed nearby region. Save its database password in the approved password manager. Invite teammates through Supabase with minimum project roles; never send passwords or service keys through chat. Record owner, region, plan limits and contacts without secrets.

## Connection and migration

Open Dashboard **Connect** and compare direct, session pooler and transaction pooler. Use the currently recommended option for the runtime. Test Alembic separately because migration/admin work may need direct or session-compatible connections. Put the URI only in backend `.env` as `DATABASE_URL`; never print or screenshot it.

```powershell
cd backend
Copy-Item .env.example .env
.\.venv\Scripts\Activate.ps1
alembic current
alembic history
alembic upgrade head
```

Review autogenerated migrations. Apply only a reviewed revision whose design, SQLAlchemy model, course SQL and dictionary agree.

## Dashboard, permissions and performance

In Table Editor confirm types, PK/FK/unique/check constraints and relationships. In SQL Editor run version-controlled SQL only. Inspect logs without copying credentials. Confirm unrestricted public access is disabled. FastAPI owns authorization; future direct browser access requires RLS and cross-user tests first. Never expose the service-role key.

Run seeds and verification queries. Use `EXPLAIN (ANALYZE, BUFFERS)` on representative joins/filters; capture before/after evidence. Add indexes only for measured needs.

## Backup, restore and reset

Before major milestones, set `DATABASE_URL` securely and run `scripts/database/backup.ps1`. Store the dump encrypted outside Git; record date, Alembic revision and row counts. Restore into a separately named safe test target, then compare revision, objects, counts and API smoke tests. Never restore over the team database.

For reset: obtain Yasmin and database-owner approval, confirm the exact development project, export a backup, then use the reviewed reset workflow. Recreate with Alembic, seeds and DBMS-object scripts. On invalid URL/password/host, timeout or outage, verify Dashboard status, connection mode, networking and URL encoding without logging the URI; retest `/api/health`. Use the migration-built local fallback and offline evidence if needed.

## Demo readiness

Freeze changes, back up, run migrations/tests, and prepare sanitized Table Editor rows plus SQL Editor JOIN, aggregate, view, routine, trigger, transaction and index evidence. Confirm React → FastAPI → Supabase and retain offline screenshots/optional recording.
