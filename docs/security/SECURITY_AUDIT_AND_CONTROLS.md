## 2. Core Security Controls

### 2.1 Password Hashing & Credential Storage
* **Algorithm:** Argon2id (via `pwdlib.PasswordHash.recommended()`).
* **Storage:** Only the salted, computed hash string is persisted in `users.password_hash`. Plaintext passwords are never logged or stored.
* **Verification:** Constant-time hash verification prevents timing side-channel attacks.

### 2.2 Stateless JWT Bearer Authentication
* **Algorithm:** HMAC-SHA256 (`HS256`).
* **Claims:** Standard `sub` (user ID as string), `email`, `role`, `iat` (issued at), and `exp` (expiration timestamp).
* **Validation:** FastAPI dependency `get_current_user` decodes and verifies signatures on every protected endpoint. Expired or forged tokens immediately trigger `401 Unauthorized`.

### 2.3 Resource Ownership & IDOR Protection
* All trip operations (`GET`, `PATCH`, `DELETE`, `generate`, `weather`, `save`) invoke `verify_trip_ownership(trip, user_id, is_admin)`.
* If a non-admin user attempts to access or mutate another user's trip, the API rejects the request with `403 Forbidden` or `404 Not Found`.

### 2.4 SQL Injection Defense
* **ORM Queries:** All application database queries use SQLAlchemy 2.0 type-safe expressions (`select()`, `where()`, `insert()`) with bound parameterized values.
* **Predefined Analytical Queries (Q01–Q18):** Run hardcoded SQL text strings without accepting dynamic user parameter concatenation.

### 2.5 Custom SQL Playground Hardening (M1 Remediation)
* **Risk Identified:** `/api/v1/reports/execute-sql` was previously unauthenticated and allowed arbitrary `SELECT` queries across all tables, including `users`.
* **Controls Enforced:**
  1. Administrative authentication required (`Depends(get_current_admin)`).
  2. Disallowed mutating keywords check (`DROP`, `DELETE`, `INSERT`, `UPDATE`, `ALTER`, `CREATE`, `TRUNCATE`, `GRANT`, `REVOKE`).
  3. Sensitive table access restriction: Any query containing references to `users`, `user_preferences`, `password_hash`, or auth credentials is automatically blocked.

### 2.6 AI Prompt Injection & Hallucination Guardrails
* The AI engine is treated as an untrusted external entity with **zero database permissions**.
* AI responses must match strict Pydantic JSON schemas.
* The system never executes SQL generated by an AI model.
